# Стандарты разработки Blazor и C# в CineNote

Данный документ регламентирует правила написания клиентского и серверного кода на платформе .NET 8, Blazor Interactive Server и C# для проекта CineNote.

---

## 1. Асинхронное программирование (Async/Await)

- **Строгий запрет синхронного ожидания**:
  - Категорически запрещено использовать блокирующие вызовы `.Result`, `.Wait()`, `.GetAwaiter().GetResult()` в компонентах и сервисах. Любая блокировка потока в Blazor Interactive Server приводит к дедлокам в сигнальном канале SignalR и зависанию UI.
  - Все методы, выполняющие операции ввода-вывода (БД, JS Interop, HTTP, файловые операции), обязаны быть объявлены как `async Task` или `async Task<T>`.

- **Сигнатура обработчиков событий**:
  - Обработчики событий Blazor (`@onclick`, `@onchange`, `@onsubmit` и др.) должны возвращать `Task`, а не `void`:
    ```csharp
    // ПРАВИЛЬНО:
    private async Task HandleSaveAsync()
    {
        await ProjectService.UpdateAsync(project);
    }

    // НЕПРАВИЛЬНО (может привести к необработанным исключениям в Blazor):
    private async void HandleSave()
    {
        await ProjectService.UpdateAsync(project);
    }
    ```

- **Отмена операций**:
  - В длительных серверных запросах и поисковых подсказках передавать `CancellationToken`.

## 2. Жизненный цикл компонентов Blazor

- **Выбор метода жизненного цикла**:
  - `OnInitializedAsync()`: использовать только для разовой инициализации компонента, не зависящей от изменяющихся входных параметров `[Parameter]`.
  - `OnParametersSetAsync()`: использовать для загрузки данных, которые зависят от параметров маршрута или родительских параметров (например, `ProjectId`), чтобы корректно реагировать на смену URL без пересоздания компонента.
  - `OnAfterRenderAsync(bool firstRender)`: использовать исключительно для взаимодействия с JavaScript через `IJSRuntime` (инициализация сторонних библиотек, фокус на элементах). Обязательно проверять условие `if (firstRender)`.

- **Вызов StateHasChanged()**:
  - Не вызывать `StateHasChanged()` избыточно в синхронных обработчиках событий (Blazor вызывает его автоматически).
  - Вызывать `StateHasChanged()` после асинхронных операций таймеров, внешних событий или вызовов через `IAsyncDisposable`.

- **Управление ресурсами и утечками памяти**:
  - Если компонент подписывается на события C# (например, `NavigationManager.LocationChanged`, события сервисов) или инициализирует JS-модули `IJSObjectReference`, он обязан реализовывать интерфейс `IDisposable` или `IAsyncDisposable`:
    ```csharp
    @implements IAsyncDisposable

    @code {
        private IJSObjectReference? jsModule;

        public async ValueTask DisposeAsync()
        {
            if (jsModule is not null)
            {
                try
                {
                    await jsModule.DisposeAsync();
                }
                catch (JSDisconnectedException) { }
            }
        }
    }
    ```

## 3. Валидация форм (EditForm и DataAnnotationsValidator)

- **Структура форм**:
  - Все формы ввода должны оборачиваться в `<EditForm Model="@model" OnValidSubmit="HandleValidSubmit">`.
  - Внутри формы обязательно размещать `<DataAnnotationsValidator />` для активации валидации по атрибутам модели.
  - Каждое поле ввода должно сопровождаться компонентом `<ValidationMessage For="@(() => model.Property)" />` с понятным сообщением об ошибке на русском языке.

- **Компоненты ввода**:
  - Использовать встроенные типизированные компоненты Blazor: `<InputText>`, `<InputNumber>`, `<InputSelect>`, `<InputTextArea>`, `<InputCheckbox>`, `<InputDate>`.
  - Не применять обычные HTML `<input>` с `@bind`, если они участвуют в валидации модели.

- **Атрибуты валидации в моделях**:
  - Все сообщения об ошибках в атрибутах `[Required]`, `[StringLength]`, `[EmailAddress]`, `[RegularExpression]` должны быть написаны на чистом русском языке без канцеляризмов:
    ```csharp
    [Required(ErrorMessage = "Пожалуйста, укажите название фильма.")]
    [StringLength(150, ErrorMessage = "Длина названия не должна превышать 150 символов.")]
    public string Title { get; set; } = string.Empty;
    ```

## 4. Требования к локализации и пользовательскому интерфейсу (UI)

- **Полная русскоязычная локализация**:
  - Весь видимый пользователю текст обязан быть на грамотном русском языке.
  - Не допускаются смешанные русско-английские термины, англоязычные заглушки ("Lorem Ipsum", "TBD", "Submit", "Cancel", "Loading...").
  - Все названия жанров, ролей соавторов, статусов сцен, кнопок, подсказок, системных уведомлений и модальных окон должны отображаться по-русски.

- **Индикация состояний (UX)**:
  - При выполнении фоновых запросов выводить спиннеры загрузки или скелетон-анимации.
  - Блокировать кнопки отправки форм на время обработки (`disabled="@isSubmitting"`), чтобы исключить повторные клики.
  - Пустые списки должны сопровождаться информативным пустым состоянием (Empty State) с иконкой, пояснением и кнопкой быстрого действия.
